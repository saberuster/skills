# Routing and retrieval

## Destinations

Use the narrowest applicable existing source. Personal scope needs explicit
support; missing project identity never means global storage. Do not create
memory locations or external records merely to place a candidate.

| Knowledge | Destination and execution |
| --- | --- |
| Explicit stable working preference | An established personal preference source or supported host memory interface, within its authorized scope |
| Confirmed project rule | The narrowest applicable AGENTS.md or supported instruction file; use available `maintain-agents-md` in the matching review, capture, or revise mode |
| Project fact or design rationale | Its canonical ADR, design document, runbook, or configured project memory; use available document editing tools and its conventions |
| Verified procedure or pitfall | A relevant existing document or skill; preserve trigger, prerequisites, action, result, and limits |
| Reusable workflow or missing skill trigger | The user-maintained skill source or its description; use available `skill-creator` for authoring and validation |
| Deterministically preventable error | A concrete lint, helper, configuration, or runtime-check proposal; implementation requires authorization for that code scope |

Confirm the selected tool or memory interface exists; never invent APIs or
install dependencies automatically. Read the matching branch below only when
its target applies: companion for instruction/skill edits, reusable operations
for workflow improvements, new memory for an authorized new memory location.

## Retrieval

Each saved lesson needs a supported reading path: an instruction scope, skill
description, or established document entrypoint. An arbitrary MEMORY.md name
does not establish loading. Report unsupported retrieval explicitly.

Place applicability, validity, and recheck conditions with the knowledge or its
actual entrypoint so ordinary tasks can check them without invoking `reflect`.
For example, verify the maintained support list before applying a workaround
limited to old clients. An uncheckable condition remains uncertain, not current
fact. Select a small relevant subset after checking scope, conditions, status,
and conflicts; usage frequency can rank knowledge, not verify or authorize it.
Expired facts are historical; age alone does not expire obligations. Distinguish
empty results from read failures, and keep long reports out of loaded guidance.

## Conditional branches

### Companion

Instruction edits require available `maintain-agents-md`; skill edits require
available `skill-creator`. If missing, leave that change as a concrete proposal
and report it incomplete; continue independent authorized document edits.
`maintain-skills` manages installations, not authoring.

Pass the lesson, evidence limits, intended behavior, authorized destinations,
visibility, existing authorization, and verification needs to the companion.
Use its authoring workflow without duplicating it or expanding a local change
into a full audit. Read target skills and supporting files before proposing
edits; a related name alone does not establish a gap.

### Reusable operations

Reuse tools first. Use instructions for judgment, templates for fixed forms,
and scripts when they reduce repeated implementation, fragile handling, or
steps. Repetition or line count alone is insufficient; simple parameterized
commands can remain examples. A script proposal names inputs, outputs,
prerequisites, failure behavior, and representative verification cases, and
belongs to the source skill that owns the task.

### New memory

Only for an explicitly authorized new file-based memory location, keep a small
index of topics, conditions, and destinations; read detailed notes on demand.
Notes and references must suit their visibility. Linking private evidence does
not make it shareable.
